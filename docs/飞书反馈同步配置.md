# Inkland 用户反馈同步飞书配置

这份文档对应 `feedback-feishu-sync-v1.sql` 和反馈同步代码。

## 1. 工作流程

1. 用户在网站提交反馈。
2. 网站先把反馈保存到 Supabase。
3. 网站服务端尝试在飞书多维表格中新增一条记录。
4. 如果飞书暂时不可用，反馈不会丢失，会标记为待补偿或失败。
5. 每天北京时间 09:00 左右，Vercel 定时任务会补传失败记录。
6. 管理员在后台点击“标记为已处理”后，网站会更新 Supabase、更新飞书记录，并给反馈用户发送一条站内系统通知。

飞书同步失败不会阻断用户提交反馈；失败原因会写入 `feedbacks.feishu_last_error`，方便排查。

> 当前定时任务负责补传网站与飞书之间的失败记录，不等同于 Codex 自动阅读和处理反馈内容。Codex 直接读取、更新飞书表格还需要单独接入可用的飞书连接能力。

## 2. Supabase 数据库

按以下顺序执行：

1. `feedbacks.sql`
2. `编号体系-v1.sql`
3. `feedback-feishu-sync-v1.sql`

第三个 SQL 会给 `feedbacks` 增加飞书记录编号、同步状态、重试次数、最后错误、处理时间和用户通知时间，并给通知表增加反馈处理通知需要的字段。

已有反馈不会被删除，也不会修改反馈原文。

## 3. 飞书多维表格字段

请建立一份专用的飞书多维表格，表格名称可以使用“反馈记录”。字段名称需要保持一致：

| 字段 | 建议类型 |
| --- | --- |
| 反馈编号 | 文本 |
| 反馈类型 | 文本 |
| 反馈内容 | 多行文本 |
| 提交人 ID | 文本 |
| 提交人昵称 | 文本 |
| 提交时间 | 文本 |
| 来源 | 文本 |
| 站内处理状态 | 文本 |
| Codex 处理状态 | 文本 |
| Codex 处理结论 | 多行文本 |
| Codex 处理备注 | 多行文本 |

程序按照字段名称写入记录。第一次联调前不要随意改字段名称；后续要调整字段类型时，需要同步检查 API 写入格式。

## 4. Vercel 环境变量

### 主项目 `inkland`

主项目负责用户提交后的即时同步和每天的补偿任务，需要配置：

```text
FEISHU_FEEDBACK_APP_ID
FEISHU_FEEDBACK_APP_SECRET
FEISHU_FEEDBACK_BITABLE_APP_TOKEN
FEISHU_FEEDBACK_BITABLE_TABLE_ID
CRON_SECRET
```

### 后台项目 `vercel-admin`

后台项目负责管理员点击“已处理”后的飞书更新和用户通知，需要配置前四个飞书变量：

```text
FEISHU_FEEDBACK_APP_ID
FEISHU_FEEDBACK_APP_SECRET
FEISHU_FEEDBACK_BITABLE_APP_TOKEN
FEISHU_FEEDBACK_BITABLE_TABLE_ID
```

后台项目原本需要的 `SUPABASE_SERVICE_ROLE_KEY` 也必须保持可用，因为后台服务端需要代表管理员写入站内通知。

所有变量都只放在 Vercel 的 Environment Variables 中，不要加 `NEXT_PUBLIC_` 前缀，也不要提交到 Git。尤其不要把 `FEISHU_FEEDBACK_APP_SECRET` 写入前端代码或发到聊天中。

## 5. 定时任务

主项目的 `vercel.json` 配置了：

```json
{
  "crons": [
    {
      "path": "/api/cron/feedback-feishu-sync",
      "schedule": "0 1 * * *"
    }
  ]
}
```

Vercel 使用 UTC，`01:00 UTC` 对应北京时间 `09:00`。定时接口只接受带有 `CRON_SECRET` 的请求。

## 6. 联调检查

合并代码并执行 SQL、配置环境变量后：

1. 前端提交一条测试反馈。
2. 检查后台是否能看到反馈。
3. 检查飞书表格是否出现一条相同反馈编号的记录。
4. 确认反馈内容、提交人和提交时间都正确。
5. 在后台点击“标记为已处理”。
6. 确认后台反馈状态变成“已处理”。
7. 确认飞书的“站内处理状态”变成“已处理”。
8. 用提交反馈的账号查看系统通知，确认收到处理完成通知。

## 7. 常见问题

### 飞书没有新增记录

先检查：

- App Secret 是否填写正确；
- 应用是否已经发布；
- 应用是否被添加到这份多维表格；
- 应用是否有多维表格编辑权限；
- App Token 和 Table ID 是否属于同一份表格；
- 字段名称是否完全一致。

### 用户反馈提交成功，但飞书没有记录

这是允许的降级行为。先在 Supabase 查询：

```sql
SELECT id, public_id, feishu_sync_status, feishu_sync_attempts,
       feishu_last_error, feishu_last_attempt_at
FROM public.feedbacks
ORDER BY created_at DESC
LIMIT 20;
```

`feishu_sync_status = 'failed'` 表示等待定时任务重试，`feishu_last_error` 会提供初步原因。

### 点击“已处理”后没有通知

检查后台项目是否配置了 `SUPABASE_SERVICE_ROLE_KEY`，以及是否已执行 `feedback-feishu-sync-v1.sql`。反馈状态和审计记录仍会保留，不会因为通知失败而丢失。
